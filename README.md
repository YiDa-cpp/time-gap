## 1. 项目简介

**时隙（TimeGap）**是一款面向长期自我学习者的桌面常驻工具。它不追求功能数量，而是用一块「安静的时钟」占据桌面的一个角落：你打开它、写下今天要学的科目、按空格开始专注，剩下的时间它只是静静走字。

> **命名由来**：「时隙」指时间被切开后留下的那些缝隙——学习的本质，就是在这些缝隙里持续投入。两个字，极简，也足够克制。

产品定位与设计哲学：

- **低视觉噪音（Quiet UI）**：默认不弹出、不闪烁、不抢焦点。所有反馈都是「你注意到时它在」的程度，而不是「它跳出来提醒你」。
- **单一焦点**：一屏之内只有一个主动作（开始/暂停），其余信息按重要性递减排布。
- **克制的反馈**：成就感通过一次水波纹、一颗小星星表达，不使用音效轰炸、不使用弹窗、不使用进度条堆砌。
- **零账号、零云同步、零遥测**：所有数据留在本机，离线可用。

### 1.1 非目标（Non-goals）

以下内容明确不做，避免范围蔓延：

- 不做多用户账号体系、不做云端同步、不做社交排行；
- 不做任务管理（To-Do）系统，只保留「当前科目」这一个标签位；
- 不做移动端 App（Tauri v2 的移动能力暂时搁置）；
- 不注册任何系统级全局热键（详见 [4.2](#42-坚决不注册全局热键)）。

### 1.2 设计原则（四条）

1. **安静优先**：任何新功能先回答「它会不会在用户专注时制造噪音」。
2. **轻量即功能**：安装包与内存占用属于产品指标，不是工程副产品。
3. **默认即最佳**：开箱就是浅蓝毛玻璃主题，用户不需要配置就能获得完整观感。
4. **可退场性**：所有沉浸式效果（全屏、置顶、贴边）都必须有一条明确的、可发现的退出路径。

## 2. 核心功能清单

优先级说明：**P0** = 首个可用版本必须有；**P1** = 第二个迭代补齐；**P2** = 打磨期实现。

| # | 功能 | 优先级 | 行为摘要 |
| --- | --- | --- | --- |
| F1 | 翻页式电子时钟 | P0 | `HH:MM:SS` 大字号数字，秒位翻页切换，非逐帧跳动 |
| F2 | 番茄钟循环 | P0 | 25 分钟专注 + 5 分钟休息，自动循环并记录轮次 |
| F3 | 沉浸全屏模式 | P1 | 隐藏边框与界面元素，仅留时钟；可一键退出 |
| F4 | 系统级免打扰 | P2 | 进入专注时尝试抑制系统通知，退出时恢复 |
| F5 | 贴边隐藏（精简短条模式） | P1 | 窗口贴屏幕边缘后收成一条「挂件」，悬停展开 |
| F6 | 专注时间统计面板 | P1 | 今日/本周/累计专注时长、番茄数、科目分布 |
| F7 | 智能学习建议 | P2 | 按上午/中午/下午/晚上四时段，每日一条方法论 |
| F8 | 任务标签绑定 | P0 | 输入当前科目，显示在时钟下方，随会话入库 |
| F9 | 背景白噪音 | P2 | 内置雨声、咖啡馆等环境音，可调音量 |
| F10 | 成就感反馈 | P1 | 番茄结束水波纹动画；今日目标达成点亮小星星 |
| F11 | 托盘常驻与开机自启 | P1 | 托盘菜单控制显示/暂停/退出；自启可开关 |

### 2.1 功能细节与验收要点

#### F1 翻页式电子时钟

- 显示格式：`00:00:00`，非专注态显示当前系统时间（`12:30:21`），专注态显示剩余倒计时。
- 数字采用**分体翻页**：每一位分为上下两半，数值变化时上半片向下翻转、下半片翻入，单次翻转 220ms（缓动 `cubic-bezier(0.4, 0, 0.2, 1)`），带轻微透视与高光。
- 秒对齐：时间推进以系统单调时钟为准，每秒在真实秒边界更新，不做 `setInterval` 累加漂移。
- 验收：连续运行 1 小时，与系统时间误差 ≤ 200ms；切到后台再回来不出现数字跳变。

#### F2 番茄钟循环

- 默认 25 分钟专注 / 5 分钟休息；一个「完整番茄」= 1 次专注完成。
- 自动流转：专注结束 → 水波纹 + 星星 + 休息开始；休息结束 → 提示回到专注，不自动开始（避免用户离开时被动进入专注）。
- 暂停、跳过、重置三种操作齐备；暂停不计入专注时长。
- 会话中断（关闭窗口、系统休眠）后恢复时，按真实时间重新核对剩余时长，不把休眠时间算作专注。

#### F3 沉浸全屏模式

- 进入后：隐藏标题栏、标签输入、统计入口、按钮组，仅保留时钟与呼吸光效。
- 退出路径：`Esc`、双击界面空白处（可配置）、托盘「退出专注模式」。
- 全屏状态不改变计时逻辑，不阻断休息提醒。

#### F4 系统级免打扰

- 目标：专注期间系统通知不打断用户，结束后恢复原状。
- 实现约束见 [5.7](#57-系统级免打扰的实现策略与风险)，采用「尽力而为 + 透明降级」策略：若系统不支持或调用失败，应用内保持沉默并在设置中给出开启系统专注助手的引导。
- 严禁：为了免打扰而修改用户电源计划、强制静音扬声器、或关闭系统级服务。

#### F5 贴边隐藏（精简短条模式）

- 触发：窗口被拖到屏幕任意边缘、距离 ≤ 8px 并停留 600ms。
- 收起形态：仅露出 12px 宽的一条玻璃质感边缘，带柔和阴影，像桌面挂件。
- 展开：鼠标进入热区即滑出（200ms），离开 1.2s 后自动收回；支持在设置中关闭该行为。
- 约束：避开任务栏区域；多显示器时贴各自屏幕边缘；贴边状态在重启后保持。

#### F6 专注时间统计面板

- 今日：累计专注时长、完成番茄数、科目分布。
- 本周：7 日柱状/折线趋势（极简点线，不用重图表库）。
- 累计：总时长、连续专注天数（streak）、最长单次专注。
- 数据来源为本地会话记录，支持「清空数据」并二次确认。

#### F7 智能学习建议

- 四个时段：上午（06:00–11:00）、中午（11:00–13:00）、下午（13:00–18:00）、晚上（18:00–24:00）。
- 每日每时段一条，从内置方法论库（≥ 40 条，涵盖间隔重复、检索练习、认知负荷、睡眠与记忆巩固等）中按「日期 + 时段」确定性选取，同日刷新页面不变。
- 纯本地、无网络请求；文案风格克制，一段不超过 50 字。

#### F8 任务标签绑定

- 单行输入，占位文案「正在学什么？」；失去焦点即保存，回车确认。
- 显示在时钟下方一行，超出省略；专注会话结束时把该标签写入记录，用于统计的科目维度。
- 标签为空时显示「未分类」。

#### F9 背景白噪音

- 内置至少两种：雨声、咖啡馆；后续可扩展「暖风扇」「溪流」。
- 生成方式优先用 Web Audio API 程序化合成为主（见 [5.8](#58-白噪音合成方案)），不引入大体积音频资源。
- 独立音量滑块，与主音量无耦合；窗口隐藏或收起为挂件时自动暂停，避免持续占用 CPU/GPU。

#### F10 成就感反馈

- 番茄完成：以时钟中心为原点扩散 2–3 圈水波纹（总时长 600ms，透明度 0.35 → 0），结束后不留残影。
- 今日目标（默认 4 个番茄）每完成一个点亮一颗小星星，星形以缩放 + 光晕点亮，不播放音效。
- 尊重系统「减少动态效果」设置：开启时降级为淡入淡出。

#### F11 托盘常驻与开机自启

- 托盘菜单：显示/隐藏窗口、开始/暂停、退出专注模式、开机自启（勾选项）、退出应用。
- 关闭窗口默认**最小化到托盘**而非退出（首次关闭时提示一次，可在设置中改为直接退出）。
- 开机自启通过注册表 Run 键实现（见 [5.9](#59-托盘与开机自启)），开关状态与系统实际状态保持一致。

## 3. UI/UX 设计规范

> 这一节是视觉与体验的「唯一事实来源」。任何实现偏差应先改本节，再改代码。

### 3.1 总体风格

高级、简约、通透。参考气质：macOS 控制中心、iOS 天气卡片、Linear 的克制排版。整体由「一张浮在浅蓝渐变光线里的毛玻璃卡片」构成，界面元素数量控制在一屏 5 个以内。

### 3.2 主题系统

软件必须自带**明暗颜色调节按钮**，三态循环：**浅色 → 深色 → 跟随系统**，按钮图标随态变化（太阳 / 月亮 / 半圆），当前选择持久化并即时生效（CSS 变量切换，不做整页重载动画）。

| 令牌（语义） | 浅色主题（默认） | 深色主题 |
| --- | --- | --- |
| 背景（底层渐变） | `#EAF4FF` → `#FFFFFF` | `#0A1428` → `#122441` |
| 主文字 / 数字 | `#1E3A5F`（深蓝） | `#A8D8FF`（亮蓝发光） |
| 次级文字 | `#5B7290`（高级灰） | `#6E86A8` |
| 强调色（进度、按钮） | `#4FA8E0` | `#5EC8FF` |
| 玻璃面板填充 | `rgba(255,255,255,0.55)` | `rgba(20,36,62,0.55)` |
| 玻璃描边 | `rgba(255,255,255,0.65)` | `rgba(94,200,255,0.18)` |
| 阴影 / 光晕 | `0 8px 32px rgba(31,84,140,0.10)` | `0 0 28px rgba(94,200,255,0.22)` |
| 分隔线 | `rgba(30,58,95,0.08)` | `rgba(168,216,255,0.10)` |

### 3.3 浅色主题（默认，明亮模式）

- 主色：明亮的浅蓝 + 纯白，背景由左上淡蓝向右下白色柔和过渡，可叠加一圈极淡的径向光。
- 质感：**毛玻璃（Glassmorphism）**——面板填充半透明白、`backdrop-filter` 模糊 20–28px、饱和度提升至 130%–150%，外加 1px 高光描边（顶部更亮，模拟受光）。
- 文字：深蓝 `#1E3A5F` 为主，辅助信息用高级灰 `#5B7290`；数字可加极淡的内阴影增强「雕刻感」。
- 观感目标：清爽、护眼、白天放在浅色桌面不突兀。

### 3.4 深色主题（暗黑模式）

- 背景：深空蓝（近黑的蓝），带极低对比的星点/噪点可选（默认关闭，避免干扰）。
- 文字：亮蓝色发光数字（`text-shadow` 光晕 8–16px，透明度控制在 0.35 以内，避免糊字）。
- 玻璃面板：深蓝半透明 + 极细亮蓝描边，光晕只在焦点元素上出现，不做整屏泛光。
- 观感目标：夜间长时间盯屏不刺眼，发光只用于「时间」这一个信息焦点。

### 3.5 字体与排版

- 数字：等宽表格数字（`font-variant-numeric: tabular-nums`），优先 JetBrains Mono / DIN 风格，回退 `ui-monospace`。时钟数字字号随窗口宽度自适应（`clamp`）。
- 中文：`"Microsoft YaHei UI"`、`"PingFang SC"`、system-ui 依次回退。
- 字重层级：时钟 300（细，显轻盈），标签 400，次级说明 400 且字号 12–13px。
- 字距：数字 `letter-spacing: 0.02em`；冒号两侧留白略大于数字间距，避免拥挤。

### 3.6 布局与尺寸

- 主窗口：默认约 420 × 260（逻辑像素），最小 320 × 200，可自由缩放。
- 垂直结构：`时钟 → 科目标签 → 状态行（轮次/建议）→ 底部操作条`。
- 安全边距：窗口内边距 24px；元素间距采用 4px 栅格（8/12/16/24/32）。
- 圆角：窗口外轮廓 20px，卡片 16px，按钮 12px 或全圆角（胶囊）。
- 精简模式：约 260 × 96，仅保留时钟与状态点。

### 3.7 微动效规范

| 动效 | 触发 | 参数 | 约束 |
| --- | --- | --- | --- |
| 呼吸灯 | 专注进行中 | 周期 6s，透明度 0.94 ↔ 1.00，光晕外扩 ±6% | 仅专注态运行；暂停/休息/空闲时完全静止 |
| 数字翻页 | 每秒 | 220ms，`cubic-bezier(0.4,0,0.2,1)` | 只翻变化的位，其余位不动 |
| 水波纹 | 番茄完成 | 600ms，2–3 圈，`scale 0.2 → 2.4`，`opacity 0.35 → 0` | 结束后 DOM 必须清理 |
| 星星点亮 | 目标进度 +1 | 400ms，`scale 0.6 → 1.15 → 1`，光晕闪烁一次 | 一次只点一颗 |
| 贴边收起/展开 | 贴边 / 悬停 | 200ms，位移 + 透明度 | 收起后不占 CPU |

所有动效必须遵循 `prefers-reduced-motion`：开启时统一降级为 ≤ 150ms 的透明度过渡。

### 3.8 可访问性与体验底线

- 文本对比度 ≥ 4.5:1（大字号数字 ≥ 3:1），深浅两套主题分别校验。
- 所有可点击元素具备可见的 hover / focus 态；键盘可达（Tab 顺序合理）。
- 不使用纯色块传达状态（专注/休息需同时用文案与颜色区分），照顾色觉差异。
- 应用整体不闪烁、不自动弹窗、不在获得焦点时抢输入。

## 4. 交互规范

### 4.1 窗口内快捷键

**仅在软件窗口获得焦点时生效**，不注册任何系统级热键。

| 按键 | 行为 | 说明 |
| --- | --- | --- |
| `Space` | 开始 / 暂停计时 | 空闲时开始专注；专注中暂停；暂停中继续 |
| `F` | 进入全屏沉浸模式 | 已在全屏时再按无副作用 |
| `Esc` | 退出全屏 / 退出沉浸 | 若存在弹层，优先关闭弹层 |

实现约束：

- 在渲染层监听 `keydown`，绑定到窗口而非全局；不使用 Tauri 的 global-shortcut 插件。
- 当焦点位于输入框（科目标签、设置项）时，`Space` 与 `F` 不触发计时/全屏，避免打字误触。
- `Space` 需 `preventDefault`，防止页面滚动或按钮二次激活。

### 4.2 坚决不注册全局热键

**这是硬性架构约束，不是建议。** 原因：全局热键会抢占其他软件的按键（尤其是 `Space`、`F` 这类高频键），属于典型的「以我为中心」的打扰设计。

落实手段：

- 依赖清单中**禁止**出现 `@tauri-apps/plugin-global-shortcut` 及任何等价 Rust crate。
- `src-tauri/capabilities/*.json` 中不得授予全局快捷键权限。
- Code Review 检查项：搜索 `global-shortcut`、`RegisterHotKey` 等关键字，出现即驳回。
- 打包前人工验证：打开记事本，在应用失焦状态下按 `Space`/`F`，确认记事本行为不受影响。

### 4.3 鼠标与窗口交互

- 拖拽：按住窗口任意非交互区域拖动（Tauri 拖拽区域），光标为 `grab`，拖动中为 `grabbing`。
- 双击时钟区域：切换全屏（与 `F` 等效）。
- 右键托盘图标：打开菜单；右键窗口内容：无自定义菜单（保持简洁）。
- 关闭按钮行为：最小化到托盘（默认），可在设置改为退出。
- 滚轮：在时钟上滚动无任何作用（避免误触改变计时）。

### 4.4 状态机

计时核心的合法状态与转换（实现须严格遵循）：

| 当前状态 | 事件 | 下一状态 | 副作用 |
| --- | --- | --- | --- |
| `idle` | 开始 | `focusing` | 记录会话开始时间、绑定科目 |
| `focusing` | 暂停 | `paused` | 冻结剩余时长 |
| `paused` | 继续 | `focusing` | 以单调时钟续算 |
| `focusing` | 计时归零 | `break` | 水波纹、星星 +1、写入会话记录 |
| `break` | 计时归零 | `idle`（待开始） | 提示回到专注，不自动开始 |
| 任意 | 重置 | `idle` | 丢弃当前会话（不计入统计） |
| 任意 | 跳过 | 下一阶段 | 标记为「未完成」，不计番茄 |

约束：`paused` 不产生统计时长；`break` 期间的界面与计时器在视觉上必须与专注态明确区分（例如呼吸光效停止、强调色转为中性）。

### 4.5 边界情况

- **系统休眠/唤醒**：唤醒后以真实时间重算剩余时长，误差 > 5 分钟视为会话中断并提示。
- **系统时间被修改**：计时内部使用单调时钟（`performance.now()` 或 Rust `Instant`），不依赖墙钟差。
- **多显示器与缩放**：窗口位置按逻辑像素保存，显示器 DPI 变化后做一次重算，避免跑到屏幕外。
- **窗口尺寸极小**：宽度 < 360px 时自动切换紧凑排版（隐藏次级信息）。
- **首次启动**：不弹引导页，直接进入可用状态，仅在托盘气泡里给一句「按空格开始」。

## 5. 技术架构选型

### 5.1 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 应用外壳 | Tauri v2（当前 CLI 2.12.x） | 体积小、原生窗口能力、Rust 侧可做托盘/自启/系统集成 |
| 前端 | 原生 HTML + CSS + TypeScript | 不使用 React/Vue，无虚拟 DOM，避免框架运行时开销 |
| 构建 | Vite（脚手架已内置） | 开发热更新、生产打包 |
| 后端（Rust） | 仅承载「Web 层做不了的事」 | 窗口控制、托盘、自启、持久化、系统免打扰 |
| 持久化 | JSON 文件（应用数据目录） | 结构简单、可手工查看；不做数据库 |
| 音效 | Web Audio API 程序化合成 | 零音频资源文件，可控、体积小 |

### 5.2 分层与职责

```
┌──────────────────────────────────────────────┐
│ WebView（渲染层）                             │
│  · 视图渲染 / 动画（CSS）                     │
│  · 键鼠事件、状态机（UI 侧）                  │
│  · Web Audio 白噪音                           │
└───────────────┬──────────────────────────────┘
                │ Tauri IPC（invoke / event）
┌───────────────▼──────────────────────────────┐
│ Rust 核心层（最小化）                          │
│  · 窗口：无边框/透明/置顶/贴边/全屏            │
│  · 托盘、开机自启                              │
│  · 会话与设置持久化（原子写 JSON）             │
│  · 系统免打扰适配（尽力而为）                  │
└──────────────────────────────────────────────┘
```

原则：**计时与统计的真相在渲染层，Rust 只做「系统能力 + 落盘」**。避免同一状态两处维护导致漂移；Rust 侧不实现计时器逻辑。

### 5.3 目录结构（规划）

```
学习计时助手设计/
├─ index.html                 # 单页入口
├─ src/
│  ├─ main.ts                 # 应用装配与事件绑定
│  ├─ styles.css              # 设计令牌（CSS 变量）与全部样式
│  ├─ core/                   # 计时状态机、会话模型、统计聚合
│  ├─ audio/                  # Web Audio 白噪音合成
│  ├─ tips/                   # 方法论库（数据）与时段选取
│  └─ ui/                     # 翻页时钟、水波纹、星星等纯视图模块
├─ src-tauri/
│  ├─ src/                    # Rust：命令、持久化、托盘、自启
│  ├─ capabilities/           # 最小权限声明
│  └─ tauri.conf.json         # 窗口形态与打包配置
├─ .vscode/
├─ package.json
└─ README.md                  # 本文档
```

### 5.4 数据模型与持久化

本地数据分为三类，统一存放于应用数据目录（`%APPDATA%\com.timegap.app\`）：

- `settings.json`：主题模式、是否置顶、贴边开关、目标番茄数、白噪音音量与音源、自启开关等。
- `sessions.json`：会话流水（开始时间、结束时间、时长、科目、模式、是否完成）。
- `stats.json`：由流水派生的日聚合（用于快速渲染，可由流水重建）。

写入策略：**先写临时文件再原子替换**，避免崩溃导致文件损坏；读取失败时回退到默认值并备份坏文件，不阻塞启动。前端 `localStorage` 仅作主题等 UI 偏好的即时缓存，不作为唯一真相。

### 5.5 Tauri 配置与能力（最小权限）

窗口形态通过 `tauri.conf.json` 配置（M0 落地）：无边框（`decorations: false`）、透明背景（`transparent: true`）、置顶（`alwaysOnTop: true`）、可缩放、最小尺寸约束、隐藏原生标题栏、Windows 下不显示在任务栏（由托盘接管，可选）。

权限原则：`capabilities` 只声明实际用到的能力（窗口、事件、托盘、自启、应用数据目录读写），不开启通用文件系统全盘访问；持久化走自定义命令而非在前端直接操作任意路径。

品牌信息同步调整：`productName` 改为「时隙」，`identifier` 改为 `com.timegap.app`，JS 包名改为 `time-gap`，Rust crate 名改为 `time-gap`（lib 名 `time_gap_lib`）。

### 5.6 渲染性能预算

- 目标：空闲时 CPU < 1%，专注态 < 3%；内存常驻 < 120MB；安装包 < 15MB。
- 时钟每秒只更新变化的数字位，其余节点不重建；动画只用 `transform` / `opacity`（走合成层），不触发 layout。
- 白噪音使用单个 `AudioContext` 与预生成的循环缓冲区，避免每秒创建节点。
- 窗口隐藏或收起为挂件时，暂停所有动画与音频，恢复时续算。

### 5.7 系统级免打扰的实现策略与风险

Windows 的「专注助手 / 勿扰」**没有公开的稳定 API**。因此该功能定位为「尽力而为」，分层实现：

1. **应用内静默**（兜底，始终生效）：不播放提示音、不弹通知、不做系统级提醒。
2. **窗口级压制**：全屏 + 置顶 + 隐藏任务栏图标，减少视觉干扰。
3. **系统集成**（可选、可降级）：尝试通过系统接口进入勿扰状态；若接口不存在、被策略禁用或调用失败，静默回退到第 1、2 层，并在设置页展示「如何手动开启系统专注助手」的一行说明。

红线：不得修改系统通知设置后不恢复；不得因免打扰失败而阻断计时；不得在未告知用户的情况下改动系统级配置。

### 5.8 白噪音合成方案

不使用 mp3/ogg 资源，全部用 Web Audio API 合成，原因：体积、版权、可调性。

- **雨声**：白噪声源 → 带通滤波（1–4kHz 区间微调）→ 少量随机短促脉冲模拟雨滴 → 轻混响。
- **咖啡馆**：粉红噪声打底 → 低频缓慢调制（模拟人群起伏）→ 偶发中频瞬态（杯碟感）→ 低通削减刺耳高频。
- 关键约束：`AudioContext` 必须在用户手势后创建/恢复（浏览器自动播放策略）；切换音源做 300ms 交叉淡入淡出，避免爆音；音量使用增益节点而非直接改 buffer 振幅。

### 5.9 托盘与开机自启

- 托盘：左键单击切换显示/隐藏，右键菜单包含计时控制与设置入口；图标提供浅色/深色两套（跟随系统主题）。
- 自启：Windows 下写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，值为当前可执行文件路径；UI 开关需读取真实注册表状态，避免「显示已开启但实际未生效」。

### 5.10 安全基线

- 生产环境启用 CSP 白名单（当前脚手架为 `null`，M6 收紧），禁止加载任何远程资源与内联脚本。
- 不引入第三方统计、崩溃上报、广告 SDK。
- 所有本地文件读写限定在应用数据目录内。

## 7. 未来高级功能规划（暂不实现）

> 以下功能已评估、留档，**当前版本不实现**。列出的技术难点与风险点是未来启动时的起点。

### 7.1 物理隔离专注码

- 设想：进入专注后若想「打断/退出」，必须输入一段随机验证码（例如 6 位数字），并且该验证码只在开始专注时展示过一次。
- 价值：把「冲动退出」变成需要付出认知成本的动作，提高专注坚持率。
- 技术要点：验证码用系统安全随机数生成，仅在内存中持有；连续输错需冷却时间；提供「正当退出」路径（如长按 5 秒 + 二次确认），避免把用户锁死。
- 风险：容易做成一款「惩罚性软件」，与「安静」的产品气质冲突，需谨慎设计文案与出口。暂不排期。

### 7.2 本地 Web API 语音播报

- 设想：剩余 5 分钟、计时结束时，通过本机语音合成播报一句简短提醒（「还剩五分钟」「专注结束，休息一下」）。
- 技术要点：优先使用系统 TTS（Windows SAPI / `SpeechSynthesizer`），经 Rust 侧调用，避免引入云端 TTS 与网络依赖；语速、音量、是否开启独立设置。
- 风险：语音会打断他人（图书馆场景），必须默认关闭；需与白噪音做闪避（ducking）处理。

### 7.3 休息时间「费曼技巧」问题抽卡

- 设想：休息的 5 分钟里，从卡片库抽一个问题（「用一句话向小学生解释你刚学的内容」「这个知识点最容易错在哪？」），帮助从「输入」切换到「输出」。
- 技术要点：卡片库本地内置、按科目/时段加权抽取；抽卡动效需极简，不能变成游戏。
- 风险：休息时间本就短，卡片可能造成压力；需要允许「跳过且不记录」。

### 7.4 动态极光 / 海浪纯色渐变背景

- 设想：专注时背景缓慢流动的极光或海浪渐变（纯 CSS 或 Canvas），深色主题下尤佳。
- 技术要点：优先纯 CSS `conic/radial-gradient` + `transform` 慢速位移，避免 Canvas 全屏逐帧绘制带来的功耗；提供「静态背景」开关。
- 风险：与「安静」原则冲突（大面积动效易分心），且显著影响续航；需做成可选、默认关闭，并提供性能降级。

## 8. 工程规范与协作约定

### 8.1 分支与提交

- 分支：`main` 保持可运行；功能分支命名 `feat/<模块>`、修复 `fix/<问题>`。
- 提交信息：`feat: 翻页时钟组件`、`fix: 暂停后剩余时间漂移`、`docs: 更新视觉令牌`、`chore: 升级 tauri`。
- 每个 PR 需说明「影响了哪个功能编号（F1–F11）」，便于回溯。

### 8.2 代码约定

- TypeScript 开启 `strict`；不使用 `any` 兜底，公共类型集中定义。
- 不使用 UI 框架；组件以「纯函数 + DOM 片段」方式组织，状态集中在单一 store 模块。
- 样式一律走 CSS 变量（设计令牌），禁止在组件里硬编码颜色；深浅主题只切换变量，不写两套样式。
- 动画参数（时长/缓动）抽为令牌，便于统一调整与降级。
- Rust 侧保持薄：一个命令只做一件事，错误统一转换为可读消息返回前端，不 panic。

### 8.3 本地开发

前置：Node.js 18+、Rust stable（含 MSVC 工具链）、Windows WebView2。

```text
npm install          # 安装前端依赖（已完成）
npm run tauri dev    # 开发模式启动桌面应用
npm run tauri build  # 生产打包
npx tsc --noEmit     # 类型检查
```

环境提示（当前机器实测）：

- 本会话 shell 的 `PATH` 未包含 `D:\CsSoftware\Rust\.cargo\bin`，需显式加入，并设置 `CARGO_HOME` / `RUSTUP_HOME`。
- 默认 npm 缓存目录不可写时，需将 `npm_config_cache` 指向可写目录。
- 在受限沙箱中，Node 子进程管道与 `CARGO_HOME` 写入可能被拦截；编译与打包建议在普通终端中执行。

### 8.4 验收清单（每个迭代结束自查）

- [ ] 无全局热键注册；失焦状态下不影响其他软件按键
